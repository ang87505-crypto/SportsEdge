## What the source bridge does

`integrations/quantconnect/source_bridge.py` maps raw LEAN-style TradeBar objects
and explicitly supplied evidence into the existing frozen selector. It evaluates
every expected permanent ID atomically. It rejects missing/extra IDs, fill-forward
bars, adjusted inputs, nonconsolidated volume declarations, stale classification,
missing action evidence, and decisions outside 2000–2011. It converts LEAN split
price factors to reciprocal new-shares-per-old-share ratios. Ordinary cash
dividends affect the total-return signal only; it does not invent payable dates
or credit a portfolio ledger. Split warnings, simultaneous split/dividend events,
mergers, spinoffs and terminations block the decision.

The new manifest requires dataset vintage, LEAN version, snapshot SHA-256,
reviewer, runtime license scope and review references for eight source topics.
These are caller declarations, **not authenticated proof**. The adapter does not
compute or verify the source snapshot hash against a stored dataset. Nor can it
infer the complete historical market from whichever IDs the caller submits.
Result flags retain `source_independently_verified=False` and
`historical_study_ready=False`, even when synthetic evidence passes every check.

The source pipeline must create a manifest in an authorized environment, preserve
the exact snapshot and authenticate its review before these inputs can support
a study. Never fill evidence fields with placeholders outside synthetic tests.
Publication times must come from source evidence; neither current download time
nor TradeBar end time proves historical availability. The caller supplies an
independently reviewed complete exchange calendar, not generated weekdays.

### Calling contract

Call `research_decision(manifest=..., members=..., sessions=..., next_session=...,
decision_at=..., strategy_version=..., incumbent_ids=..., equity_cents=...)`.
Each member contains `symbol`, `metadata`, and `observations`. The source and test
docstrings describe every field. `test_source_bridge.py:source_fixture` is an
executable **synthetic schema example**, never a market-data source.

Map the result to a future execution contract containing strategy version,
decision timestamp, permanent ID, dated ticker, target budget, source snapshot
hash, input provenance and reason codes. It is not an order ticket. Broker
quantity, execution feasibility, settled cash, costs, partial fills, reconciliation
and reviewed risk gates remain the separate execution engine's responsibility.

## Event prototype boundaries and next contract

`analytics/stock_event_shadow.py` is a bounded offline in-memory prototype,
with no network fetcher, scheduler, database, LLM or broker. It accepts only SEC
or Federal Reserve envelopes through allowlisted HTTPS URLs and caller-supplied
transport receipts. TLS flags/hashes do not authenticate a malicious caller:
production collectors must produce trusted receipts after TLS and redirect checks.
Body size and queue capacity are bounded; overflow fails rather than deleting data.

Each envelope carries source URL, ID, revision, publication/observation/update
times, issuer identity, status, content hash and collector version. Mapping rows
carry security ID, ticker, optional sector, effective interval, availability and
evidence reference. Multiple classes or ambiguous mappings are quarantined.
Original and corrected revisions remain separately accessible as of the decision.
Deletion revisions quarantine future assessments without rewriting past ones.

Outputs retain hashes, age/delay, category, mapping status and unknown materiality,
novelty, horizon, direction and probability. A hash chain supports audit inspection
but is not a tamper-proof durable log. Exact duplicate handling is within one
canonical source event; cross-source headline deduplication is not implemented.
The prototype never interprets body instructions and always forbids orders.

For production shadow collection: authenticate the collector, persist append-only
receipts transactionally, enforce source-specific rate limits/backoff, deduplicate
by canonical ID plus revision, and measure processing/queue delay. Add schema-
constrained classification only after simple form/category baselines are scored.
No hypothesis may turn a language model's textual confidence into order authority.
No prospective collection has been activated by this PR.
